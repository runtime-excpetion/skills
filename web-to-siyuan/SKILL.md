# 网页剪藏到思源

把网页链接**高保真剪藏**进思源笔记：抓取正文转成 Markdown，在思源里新建一篇独立文档。一次可处理多个链接。

## 输出契约

每篇成功创建的文档必须满足以下要求：

1. 正文开头包含可点击的原文地址，使用用户提供的 URL，不得用抓取缓存地址或省略：

   ```markdown
   > 原文地址：[https://example.com/article](<https://example.com/article>)
   ```

   若发生重定向，第一行仍保存用户提供的原始 URL；仅当最终 URL 不同时，再增加一行 `> 最终地址：[...]`。
2. 原文的标题层级、段落、列表、引用、表格、分隔线、图片、行内代码和代码块尽量保持原结构。
3. HTML 的 `<pre>`、`<pre><code>` 及常见代码高亮容器必须转换为 fenced code block，不能作为普通段落平铺。
4. 代码块必须保留换行、缩进和符号；能识别语言时写语言标记，无法识别时使用无语言标记的围栏。
5. 创建文档前执行“写入前检查”；来源地址缺失、疑似代码被平铺或 Markdown 围栏不闭合时，先修复，不得直接写入。
6. 来源区块与第一段正文之间只能有一个空行；正文中不允许出现连续空白段落或页面脚本。

## 配置

思源实例地址、API token、目标笔记本、文档目录**不硬编码在本 skill 里**，统一存在配置文件：

路径：`~/.config/siyuan-clipper/config.json`

```json
{
  "url": "https://your-siyuan.example.com",
  "token": "你的 API token",
  "notebook": "04-Archive",
  "directory": "/09-Inbox"
}
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `url` | 是 | 思源实例地址，不带末尾斜杠 |
| `token` | 是 | API token（思源「设置 → 关于」里查看） |
| `notebook` | 否 | 目标笔记本名；留空则用第一个未关闭的笔记本 |
| `directory` | 否 | 笔记本内的文档目录路径，如 `/09-Inbox`；留空则存到笔记本根目录 |

首次运行（配置文件不存在或缺 `url`/`token`）时向用户询问并保存，详见步骤 2、3。

## 步骤

### 1. 解析链接

从用户输入中提取全部 `http`/`https` 链接，去重。

若输入中没有链接，停止并提示用户提供链接。

**完成条件**：已取到至少一个待剪藏的网页 URL。

### 2. 加载或初始化配置（url / token）

1. 读 `~/.config/siyuan-clipper/config.json`。
2. 若文件存在且 `url`、`token` 均非空，载入之，跳到步骤 3。
3. 否则视为首次运行，用 AskUserQuestion 向用户询问：
   - 思源实例地址（URL，如 `https://note.example.com`，去掉末尾斜杠）
   - API token

   拿到后立刻调 `lsNotebooks`（方法见 `reference/siyuan-api.md`）验证连通与鉴权。失败则把错误（HTTP 状态码 / 返回 `msg`）反馈用户、停下等用户修正，**不要把错误的 url/token 写进配置**。成功后 `mkdir -p ~/.config/siyuan-clipper`，把 `url`、`token` 写入配置文件（`notebook`、`directory` 此时留空，下一步再补）。

**完成条件**：已拿到可用的 `url` 与 `token`，并已持久化到配置文件。

### 3. 选定笔记本与目录

调 `lsNotebooks` 取笔记本列表（每项含 `id`、`name`、`closed`）。

**笔记本**按以下优先级确定（前一条命中即停）：

1. **本次输入指定了笔记本名** → 按 `name` 精确匹配；匹配不到则停止，把可用（未关闭）笔记本名列出来提示用户。本次指定**只影响这一次**，不写回配置。
2. **配置里的 `notebook` 非空** → 在列表里按 `name` 匹配未关闭笔记本，命中则用其 `id`；命中不到则告警并走第 3 条。
3. **配置里 `notebook` 为空**（首次运行或用户当初留空）→ 用 AskUserQuestion 列出未关闭笔记本供用户选择；用户留空则兜底取**列表中第一个 `closed` 为 `false` 的笔记本**。

   若是首次运行（配置里 `notebook` 还为空），把最终确定的笔记本 `name` 写回配置文件，后续运行不再询问。

**目录**取配置里的 `directory`（如 `/09-Inbox`）。首次运行若为空，在询问笔记本时一并询问用户；留空则存到笔记本根目录（文档路径直接是 `/<文档名>`）。把结果写回配置。目录名做规范化：确保以 `/` 开头、去掉末尾 `/`；值为空或 `/` 表示根目录。

最终文档路径 = 目录前缀 + `/` + 文档名（根目录时为 `/<文档名>`）。

**完成条件**：已确定目标笔记本 `id` 与文档目录前缀。

### 4. 逐条剪藏

对每个链接依次完成：

- **保存来源信息**：把用户输入中的 URL 记为 `original_url`，贯穿整个处理过程。重定向后的 URL 只能另记为 `final_url`，不得覆盖 `original_url`。
- **规范化 URL**：移除 Markdown 链接包裹以及误粘在链接末尾的中文逗号、句号等标点。例如 `https://example.com/a，` 必须规范成 `https://example.com/a`。
- **抽取正文**：抓取链接，取标题与正文转为 Markdown，并把正文中的**所有图片上传为思源资产**、改写引用。按页面形态选路：
  - 普通文章：可先用 WebFetch 判断正文范围。只要原网页含代码或抽取结果疑似丢失结构，就改用原始 HTML 管线处理，不能把 WebFetch 的纯文本结果直接写入思源。
  - 技术文章：优先获取原始 HTML，以正文 DOM 为输入；在段落清洗与文本归一化之前，先抽取并保护代码节点。
  - 微信公众号：必须用 curl 获取原始 HTML，再调用 `scripts/html_to_markdown.py`；只允许提取 `#js_content`，禁止按整页文本或字符串区间抽取。
  - 若返回验证页或内容不完整，记录失败，不得把验证页或残缺正文写入思源。
  - 全图文章：抽取后文字内容为空，正文按原序只含图片引用。

  代码转换、抓取、资产化与形态判定细节见 `reference/siyuan-api.md`。若彻底抓取失败（需登录、404），记录失败原因，跳过该链接，继续下一个。
- **组装 Markdown**：在正文最前面插入来源区块，然后空一行再接正文。不要重复网页的 H1 标题，因为文档标题已由 `path` 创建。格式固定为：

  ```markdown
  > 原文地址：[{original_url}](<{original_url}>)

  <正文>
  ```

  若 `final_url` 与 `original_url` 不同，在原文地址下一行增加最终地址。
- **写入前检查**：逐项确认：
  - Markdown 中包含完整且可点击的 `original_url`。
  - 每个 fenced code block 都有闭合围栏，围栏前后各有空行。
  - 来源区块后只有一个空行，正文中不存在连续的纯空白段落。
  - 原 HTML 中每个正文 `<pre>` 至少对应一个 Markdown 代码块；`<code>` 中含换行的内容不得变成普通段落。
  - 代码缩进和换行仍存在，HTML 实体已在代码内容中正确解码，且代码没有被误当作 Markdown 标题、列表或链接解析。
  - 行内 `<code>` 转成单反引号或足够长的反引号包裹，不与 fenced code block 混淆。
  - 来源区块、代码围栏和正文图片顺序正确。
  - 正文不包含 `document.getElementById('js_content')`、`document.addEventListener`、`selectstart` 等页面脚本特征；命中时视为正文边界错误，禁止写入。
- **新建文档**：检查通过后，调用思源 API `createDocWithMd` 创建文档，`markdown` 取已组装的完整 Markdown；`path` 写完整路径（步骤 3 确定的目录前缀 + 文档名），文档名取网页标题（方法见 `reference/siyuan-api.md`）。记下返回的新文档 ID。

**完成条件**：每个链接都已尝试剪藏——成功者拿到文档 ID，失败者拿到原因，无遗漏。

### 5. 汇报结果

逐条列出剪藏结果：网页标题、原文地址、成功或失败、失败原因（若有）；另报告代码块数量与图片状态（已上传数量、保留外链的张数）。成功者附思源文档链接 `siyuan://blocks/<文档ID>`，可直接点击打开。

**完成条件**：所有链接的处理结果均已报告。

### 6. 临时文件清理

抽取的文章、图片等缓存文件，在处理结束后删除。

**完成条件**：本次剪藏产生的临时文件已全部删除。
